# 録音と音源付きバックアップ

## ミックス録音

- MediaRecorder のエンコード済み音声を原則 1 秒ごとに IndexedDB に保存します。録音全体の PCM や音声配列を JavaScript メモリへ蓄積しません。
- 未保存チャンクの合計上限は 8 MiB。保存が追いつかない場合や容量不足では録音を停止し、保存できた範囲を録音一覧に残します。チャンクと保存済みバイト数は同一トランザクションで更新します。
- 再読み込みや予期しないタブ終了後も、保存済みチャンクを一覧から書き出せます。OS に終了された時点の未保存部分は失われます。ブラウザのデータ消去に備え、録音後はファイルも保管してください。
- 完了時にも録音全体を自動デコードしません。長時間録音をライブラリへ取り込む場合は、従来の音源サイズ・デコード容量制限が適用されます。
- ファイルへの直接書き込み対応ブラウザでは、保存済みチャンクを順番に書き出します。それ以外では Blob をまとめてダウンロードします。この場合の大容量ファイル保存はブラウザの Blob 実装・空きメモリにも依存します。
- 未終了のコンテナー（特に MP4）は最後のメタデータが欠け、保存済みバイトを取り出せても再生できない場合があります。クラッシュ後の全形式・全端末での再生を保証する機能ではありません。

## 音源付きバックアップ

拡張子 `.seekdeck` の 1 ファイルに、元の音源、曲情報、キュー、クレート順序、デッキ・ミキサー・UI 配置・コントローラー割当を格納します。波形画像用の派生データは除き、曲のロード時に再生成します。未整理の録音一覧は別に書き出してください。

- 音声を base64 に変換せず、元のバイナリを連結します。
- 4 MiB ごとの SHA-256 とメタデータの SHA-256 を照合してから復元します。音声全体を一度に `arrayBuffer()` へ展開しません。
- 曲・音源・セッションは同じ IndexedDB トランザクションで保存します。破損、保存失敗、トランザクション中断時に一部だけ置き換わることを防ぎます。
- 復元は同じ ID の曲を更新し、その他の既存曲と録音一覧は保持します。セッションとクレートはバックアップの内容になり、デッキの再生は停止状態になります。
- 20,000 曲、音源合計 128 GiB、メタデータ 64 MiB が形式上の上限です。端末の実容量やブラウザ制限によって、それより前に保存が拒否される場合があります。
- チェックサムは破損検出用であり、暗号化・署名ではありません。

## 形式 v1

| 順番 | 内容 |
| --- | --- |
| 1 | UTF-8 固定文字列 `SEEKDECK-BACKUP1` と LF（16 バイト） |
| 2 | マニフェスト長：符号なし 32 bit little endian |
| 3 | マニフェスト UTF-8 バイト列の SHA-256（32 バイト） |
| 4 | JSON マニフェスト：format/version/chunkBytes/createdAt/tracks/session/audio |
| 5 | audio 配列順の音声本体。各要素の size と 4 MiB 単位の chunks ハッシュで境界・内容を検証 |

録音は IndexedDB `orbit-dj-local` version 2 の `recordings` と `recordingChunks` に保存します。既存の version 1 曲・音源・セッションはマイグレーションで保持します。

## 検証

Node テストは音声込みラウンドトリップ、破損・切り詰め・余分なバイトの拒否、4 MiB を超えない音声読み出し、保存遅延・容量不足時の上限と順序を確認します。ブラウザテストは実 IndexedDB のロールバック、再読み込み後の録音回収、実 MediaRecorder の録音・デコードを確認します。スマホ実機での長時間録音・OS による強制終了は別途実機確認が必要です。
