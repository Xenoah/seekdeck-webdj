# スマホ実機の検証

自動テストはブラウザ上のイベント処理と音声エンジンの動作を検査します。Android / iPhone 実機、実際の着信、Bluetooth、USBオーディオ機器の測定結果ではありません。

## 実装した保護

- 音声が `suspended` / `interrupted` になったら、デッキを停止して位置と再生中だったデッキを記憶します。OSが音声出力を復帰させても演奏を自動再開しません。
- 「演奏を再開」は中断直前のデッキだけを復帰します。その後に明示停止・曲のロード・セッション復元を行ったデッキは再開対象から外れます。
- CUE専用のAudioContextが中断された場合も全デッキを止めます。再開前にMASTER / CUE両方の出力を確認します。
- 中断時は一時的なジョグ／ロール／サンプル再生を解除します。サンプルは再度パッドを押して開始します。
- 画面点灯の保持は設定で有効にした場合のみ、画面が表示され音声エンジンが動作している演奏・録音中に要求します。全停止・非表示・ページ移動で解除します。省電力などの拒否を繰り返し要求しません。
- ページ移動・再読み込み後は停止状態です。中断前の再生意図は端末に保存しません。
- 設定から端末診断JSONを保存できます。最大100件の状態履歴、画面サイズ、ブラウザ報告の遅延、メインスレッドのタイマー遅延を含みます。音源、曲名、保存パス、機器IDは含みません。

## 実機確認表

機種名、OSとブラウザのバージョン、出力機器、アプリバージョンを記録し、各端末で確認します。

| 確認 | 操作 | 合格条件 |
| --- | --- | --- |
| 2デッキ操作 | 横画面で左右ジョグ・ロールを同時に操作し、指を逆順に離す | 両方の解除が反映される。飛び・音の張り付きがない |
| 画面回転 | 2デッキをループ再生し、横→縦→横を10回 | 再生、フェーダー、デッキ選択が維持される |
| 画面点灯保持 | 設定をON、通常の自動消灯時間より長く再生。その後全停止 | 許可された端末は再生中点灯し、全停止後は保持が解除される |
| 着信・他アプリ | 通話の着信と応答、別アプリの音声再生、元画面へ復帰 | 中断を認識し、突然再開しない。再開操作で期待したデッキだけが戻る |
| 明示停止 | 中断後に片方のデッキを停止し、「演奏を再開」 | 停止したデッキが勝手に戻らない |
| 消灯・復帰 | 電源ボタンで消灯し、ロック解除して復帰 | OSが停止した場合は中断表示。勝手な演奏再開がない |
| USB / CUE | 有線USB機器の接続、CUE単独試聴、MASTERとの切替、取り外し | 各チャンネルの割当が正しく、再接続後の出力を確認できる |
| 長時間演奏 | 60分、2デッキ、選曲・ループ・FX・録音を通常操作 | 音切れ、クラッシュ、保存失敗がない。録音の長さと内容が期待どおり |
| 再読み込み | キュー・設定を保存してページを再読み込み | 設定と曲が残り、全デッキが停止状態 |

機器の抜き差しがブラウザから音声中断として通知されない場合があります。実際の出力先が切り替わったことまでは自動判定できません。

## 遅延の測定

診断の `browserReportedBaseLatencyMs` と `browserReportedOutputLatencyMs` はブラウザの値です。操作から実際の出音までの遅延ではありません。`physicalInputToSoundLatencyMs` は未測定を表す `null`、`physicalLatencyMeasured` は `false` として出力します。

実測する場合は、入力接点／パッド操作の基準信号とアナログ音声出力を同じレコーダーまたはオシロスコープで取り込み、立ち上がりの差を測ります。複数回の中央値と最大値、出力機器、有線／Bluetoothの別を残します。映像で指と音を比較する簡易測定は、カメラの映像／音声同期誤差も記録します。

`foregroundTimer.maxSchedulingGapMs` は1秒タイマーの予定より遅れた時間です。音声スレッドのアンダーラン回数や音切れを示す値ではありません。
