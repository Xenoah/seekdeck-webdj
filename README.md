# SeekDeck

プロジェクト／リポジトリ名は `seekdeck-webdj`、アプリ名は **SeekDeck** です。

ローカル処理のブラウザDJアプリ。依存ライブラリ・APIキー・バックエンド・音源アップロードを必要としない静的ES Modulesアプリです。再生を含むWeb APIはHTTPSまたはlocalhostが必要です。

`dist/` を静的ホストから配信します。ファイルを `file://` で開く形式には対応しません。初回起動後はService Workerでアプリと4つのオリジナルデモをキャッシュします。音源を扱うリクエストは同じオリジンのデモ音源のみです。ユーザー音源はIndexedDBへ保存します。

## リリースとGitHub Pages

[最新版と配布ZIP](https://github.com/Xenoah/seekdeck-webdj/releases/latest) · [変更履歴](releases/)

[SeekDeckを開く](https://xenoah.github.io/seekdeck-webdj/)

Pagesは次の両方式に対応しています。設定は [Settings → Pages](https://github.com/Xenoah/seekdeck-webdj/settings/pages) で確認できます。

- **Deploy from a branch → main → / (root)**：通常の公開URLから自動的に `dist/` のDJ画面を開きます。READMEを入口にしません。すでにこの方式なら変更不要です。
- **GitHub Actions**：[GitHub Pages](https://github.com/Xenoah/seekdeck-webdj/actions/workflows/pages.yml) の **Run workflow** を実行すると、`dist/` を公開ルートとして配信します。以降のアプリ更新はテスト後に自動配信します。

二つの配信処理の競合を避けるため、ワークフローはPagesの公開方式を確認してから配信します。

初回有効化には管理権限が必要です（[GitHub公式の権限要件](https://github.com/actions/configure-pages/blob/main/action.yml)）。オリジンごとに音源と設定の保存領域は分かれます。

## 起動方法

配布ZIPを展開するか、このリポジトリを取得します。Python 3がある環境では、プロジェクトのフォルダーで次を実行してください。追加パッケージは不要です。

```sh
python -m http.server 8000 --bind 127.0.0.1 --directory dist
```

ブラウザで `http://localhost:8000` を開き、デモ曲の再生ボタンを押します。Windowsで `python` が見つからない場合は `py -3` を使用してください。停止はターミナルで `Ctrl+C`。音声・機器APIの対応はブラウザと実機に依存します。

HTTPSの静的ホストへ配信する場合は、`dist/` の内容を配信ルートに置きます。開発時の検証にはNode.js 24で `npm test` と `npm run check` を実行します。`npm install` は不要です。

## 波形の配色

波形パネルで **RGB / 3 BAND / DECK** を切り替えられます。RGBは低域を赤、中域を緑、高域を青に対応させ、音源の帯域別エネルギーから色を決めます。3 BANDは低域を青、中域を橙、高域を白で積み重ねて表示します。選んだ配色は保存されます。既存の単色波形は次に音源をロードした際に更新します。解析はWorkerで小分けに処理し、オーディオ処理とは分離しています。rekordboxの波形キャッシュを読み込む機能ではありません。

## 実装範囲

- 4デッキ、AudioWorklet PCM再生、可変速度、逆再生、ジョグ、スクラッチ、SLIP
- 8ホットキュー、可変BPMグリッドの量子化、マニュアル／自動ループ、ロール、ビートジャンプ
- BPM／キー推定Worker、グリッド編集、TAP、拍位置・テンポを追従する継続SYNC
- TRIM、3バンドEQ、フィルター、Echo／Reverb／Flanger、フェーダー、クロスフェーダー割当と3曲線
- 独立したキー／テンポ操作（試験的な2-grain overlap-add DSP。商用DSP音質とは非同等）
- 8サンプル、最大16ボイス、最大30秒の範囲指定
- MASTER録音、CUEのステレオ分岐／4ch／別デバイス出力（API・機器依存）
- 24列グリッドで移動／リサイズ／表示切替、名前付き配置、3プリセット、30操作Undo／Redo
- 音源・曲情報・クレート・キュー・配置・ミキサー・MIDI/HID割当をIndexedDBに保存
- 再生位置を5秒ごと＋pagehide時に保存。復元時には自動再生しない
- セッションと曲情報のJSON入出力（音声は別）、元音源のダウンロード
- MIDI Learn（Note／CC／Pitch Bend）、14-bit CC、相対3形式、Note / CC LEDフィードバック、DDJ-400基本プリセット
- 接続・切断時の保持解除、入力ポートごとの状態分離、JSONの厳密検証。仕様と実機未検証の範囲は[コントローラープロファイル](docs/controller-profiles.md)
- HID入力レポートの機種別バイトマッピングJSON。ハンドシェイク／専用出力は非対応
- rekordbox XML / Traktor NML / M3U8 / PLS / CSV / Serato crateのローカル入出力。読み込みプレビューとパス照合
- WebMCPの状態読取、配置プリセット、停止デッキへの一括ロード（対応ブラウザのみ）

## 未実装・制限

**Rekordbox / Serato DJの完全な代替ではありません。全DJコントローラー対応を保証しません。**

AIステム分離、DVSタイムコード、動画／照明、配信サービス、各社独自データベース、CDJ USB書出、メーカー独自の機器初期化・液晶・モーターは未実装です。HIDは既知のレポート形式と対応ブラウザが必要です。すべてのハードウェアの実機テストは未実施です。

EQはWeb Audio BiquadFilter、リミッターはDynamicsCompressorです。放送用true-peakリミッターではありません。Granularキー固定は音源によって位相・トランジェントのアーティファクトを生じます。サーバーへの音源送信やクラウドAI処理で代用していません。

解析は冒頭最大180秒、推定BPM 65〜180、手動入力20〜400。SYNCはMASTERのテンポと拍位置へ継続追従します。可変BPMは手入力・読み込みしたテンポマップを使用し、自動解析は一定BPMの推定です。元ファイルのメタデータタグは解析せずファイル名の `Artist - Title` を分割します。コーデック対応は `decodeAudioData` に依存します。

上限：元音源300 MiB／曲、1時間／曲、デコードPCM合計512 MiB、4デッキ＋8サンプルの音源を保持。読み込み時には一時的なPCMコピーが発生するため実際のプロセスメモリは上限を超えます。大容量音源・モバイルではメモリ制限に注意。録音は停止までメモリ保持します。

保存は端末・ブラウザ・オリジン単位。JSONに音声データは含みません。ブラウザデータ削除やストレージ退避時に消えるため、元音源とJSONを保管してください。保持リクエストはブラウザが拒否する場合があります。

名称変更後も旧 ORBIT DJ の保存データを引き継ぐため、IndexedDBとlocalStorageの識別子、およびセッションJSONの形式名は維持しています。

## 検証

`npm test` はPCM処理をNodeで実行し、4出力・時間進行・ループ・逆再生・SLIP／ロール復帰・サンプル出力・音程処理を検証します。BPM解析を既知クリック信号で検証し、保存データ正規化／MIDIデコード／クロスフェード／拍位置同期も検証します。`npm run check` は構文・ローカル参照・Service Workerキャッシュ一覧を確認します。

GitHub Actions上のChromiumでサブパス起動・波形描画・音声再生中の解析・スマホのタッチ操作・状態復元を検証します。機器接続テスト・実測レイテンシー・長時間連続演奏・音質評価は未実施です。WebMCPは対応ブラウザでの検証環境がないため未検証です。

## 構成

- `dist/audio/processor.js`: AudioWorklet用PCMトランスポート。描画とは独立。サンプル計算ループではメモリ確保せず、25 Hzで状態メッセージを送信
- `dist/audio/engine.js`: Web Audioルーティング、EQ、FX、出力、録音、PCMキャッシュ
- `dist/audio/analysis.js`: 自己相関BPM・Goertzelクロマのキー推定Worker
- `dist/app.js`: 状態・演奏操作・保存制御
- `dist/events.js`, `ui.js`, `visuals.js`, `dialogs.js`: UIとイベント
- `dist/storage.js`: IndexedDBトランザクション
- `dist/controllers.js`: MIDIとHIDの入力プロファイル
- `tools/generate-demos.py`: 4つのオリジナル合成デモの再生成（NumPy使用）

## スマートフォン

スマホは**横画面での演奏**を主軸にしています。幅859px以下（タッチ端末は1100px以下）で専用UIになり、横向きかつ幅560px以上では左右2デッキ＋中央ミキサーを同時に表示します。djayのクラシックなターンテーブルとミキサーの構成を参考に、SeekDeckの操作・配色で実装しています。

- 上部のA/BまたはC/Dでデッキの組を選択。再生・CUE・SYNCと中央のクロスフェーダーは常時操作できます。
- 各デッキの **JOG / PADS / FX・TEMPO** を切り替えて演奏。中央ミキサーは通常の音量・フィルター表示と、メニューのミキサーから開くEQ表示を切り替えます。
- デッキのフォルダボタンから、そのデッキを対象に選曲できます。曲をロードすると演奏画面に戻ります。曲一覧とサンプラーは画面全体に表示します。
- 設定にはマスター音量・録音・波形配色・コントローラー操作をまとめています。
- 選択したデッキ・各操作パネル・ミキサー値を保存します。画面回転やメニュー切り替えは再生を継続し、SYNCのMASTERやPCの保存配置を変更しません。再読み込み時は停止状態で復元します。

縦画面では1デッキと下部メニューを表示し、横向きへの案内を出します。ホットキューの削除は「キュー削除」、サンプル編集は「パッドを編集」を有効にしてからタップします。短い横画面ではパッドや詳細操作の内側だけをスクロールできます。セーフエリアと動的な画面高さに対応しています。実機の音声出力・MIDI/HID対応はブラウザと端末に依存します。

## 他ソフトとのファイル交換

ライブラリの「···」→「他ソフトと読み込み / 書き出し」から利用します。

| 形式 | 曲情報・BPM・キー | キュー・ループ | 曲順 |
| --- | --- | --- | --- |
| rekordbox XML | 対応 | 8ホットキュー、ループ、メモリー、名前・色 | 対応 |
| Traktor NML | 対応（INFO KEY） | 8ホットキュー、ループ、メモリー、名前 | 対応 |
| M3U / M3U8 | 曲名・長さのみ | なし | 対応 |
| PLS | 曲名・長さのみ | なし | 対応 |
| CSV | 対応 | 8キュー、追加JSON列でループ・メモリー | 対応 |
| Serato .crate | パスのみ | なし | 対応 |

1. 元音源を先に登録します。「音源フォルダーを追加」は相対パスも保持します。
2. 交換ファイルを選び、一致・未登録・同名重複・未対応パスを確認します。未一致は更新せず、照合結果をCSVへ保存できます。
3. 曲情報を上書きするか選択して読み込みます。音源の実際の長さ・波形は維持します。記載のあるキューだけ上書きし、未記載キューは保持します。プレイリストは新しいクレートとして追加します。
4. 書き出しは全コレクション・お気に入り・個別クレートを選択します。XML/NMLは複数クレート、その他は一つの曲順を書き出します。

XML/NMLには元音源の絶対パスが必要です。ブラウザは元の絶対パスを取得できないため、`C:/Music` または `/Users/me/Music` などを指定します。読み込んだ元パスを優先する設定もあります。フォルダー取り込み時の相対パスには選択したフォルダー名が含まれるため、指定する基準はその親フォルダーです。書き出したファイルのパスが実ファイルを指すことを確認してください。

Serato crateは `_Serato_` の親を基準とする相対パスを保存します。絶対パスを使う場合は「Serato crate基準フォルダー」を指定し、その配下の `_Serato_/Subcrates` に書き出したファイルを配置する用途です。別ドライブの音源は別々に書き出します。Seratoのdatabase V2、解析キャッシュ、音声タグ内のキューは読み書きしません。

CSVはUTF-8（BOM付で出力）です。`path` / `location` / `filename` 列が必須。`title,artist,album,genre,bpm,key,comment,duration,grid_offset,rating,cue1`〜`cue8` を認識します。時間は秒です。`cueDetails` と `memoryCues` はSeekDeck用のJSON配列列で、他ソフトが認識するとは限りません。カンマ・セミコロン・タブ区切りと引用符内の改行を読み込めます。書き出しは表計算で数式として実行される文字列をエスケープし、SeekDeckで読み戻すと元の文字列に復元します。

上限は1ファイル25 MB・20,000曲・合計300クレート。UTF-8以外のテキスト、リモートURLの音源取得、圧縮済み独自ライブラリDB、CDJ USBデバイス書き出しは対象外です。XML/NMLのプレイリスト階層は平坦化し、可変テンポ／複数グリッドは先頭のみ使用します。メモリーキューは最大128個の保存と再出力に対応し、演奏パッドはホットキュー0〜7に対応します。

互換形式の一次実装と独立したテストデータは [tests/fixtures](tests/fixtures/) に記載しています。各社アプリ全バージョンの実機読み込み検証は未実施です。

## 演奏の安定性とSYNC

同時タッチは指ごとにジョグ・ロール・ナッジを管理し、画面切替や中断で確実に解除します。音声出力が中断された場合は位置を保って停止し、設定の「音声・演奏を再開」で復帰します。画面点灯保持は設定から有効にできます。

[スマホ確認手順](docs/mobile-verification.md) · [継続SYNCと可変グリッド](docs/audio-sync.md)。端末診断の遅延値はブラウザの報告値で、実機の操作から発音までの測定値ではありません。キー固定のステレオ信号処理を修正しましたが、商用DSPと同じ音質を保証するものではありません。
